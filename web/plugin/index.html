Wildy Slayer · RuneLite companion

The plugin

Syncs your own levels, bank and current task to the Wildy Slayer app, outlines the gear it picked in your bank, lists your saved setups and hands the spot to Shortest Path.

Open the app README (plain text) Sync protocol (plain text)

What it does

  • Sync (opt-in, off by default). While you are logged in, the plugin pushes a snapshot of your character to the server at most once every 2 seconds and polls every 5 seconds for the selection and setups the app wrote. Everything is keyed by an 8-character pairing code.
  • Bank highlights. The app's picks are outlined green, the next-best alternatives yellow, the "what to bring" supplies cyan, in the bank, inventory and equipment tab. Each is a toggle.
  • Side panel. Sync status, your current task, the app's selection (task, spot, style, setup) with one row per gear slot saying whether the item is worn, in your inventory, in the bank or missing, and your saved setups with an Apply button each.
  • Shortest Path. "Walk there" sends the selection's spot to the Shortest Path plugin, which draws the route on the map. Nothing moves your character.
  • Info overlay. A small on-screen box with the task, spot and setup name.

Install

The plugin is not on the Plugin Hub yet. Current RuneLite only turns on developer mode, which sideloading needs, when the client was not started by the RuneLite launcher and Java assertions are on (RuneLite.java: options.has("developer-mode") && RuneLiteProperties.getLauncherVersion() == null, then an -ea check). So a jar dropped into ~/.runelite/sideloaded-plugins/ is never loaded by the RuneLite you install from runelite.net or start from the Jagex Launcher, whatever its settings. Until the plugin is on the Plugin Hub, you run it in a development client built from this source.

Run it from source (macOS, Linux, Windows)

  1. Java 17. macOS with Homebrew: brew install --cask temurin@17. Otherwise install Temurin 17 from adoptium.net. Check with java -version; if several are installed, on macOS run export JAVA_HOME=$(/usr/libexec/java_home -v 17) first.
  2. The source. git clone https://github.com/Zlerp/wildy-slayer, or on the repository page use Code, Download ZIP and unzip it.
  3. Run it. In that folder: chmod +x gradlew once, then ./gradlew run (Windows: gradlew.bat run). The first run downloads Gradle and the RuneLite client, a few minutes. A RuneLite window opens with Wildy Slayer already in the plugin list.
  4. Log in. An old-style username and password account logs in as usual. A Jagex account cannot log in to a development client directly: once, start your normal RuneLite from the Jagex Launcher with the client argument --insecure-write-credentials (set it in the launcher's configuration window, /Applications/RuneLite.app/Contents/MacOS/RuneLite --configure on macOS, launcher 2.6.3 or newer), log in, and it writes ~/.runelite/credentials.properties. The development client then logs in with that file. It is a login token: keep it private, and delete it and remove the argument when you are done. Details: Using Jagex Accounts.
  5. Install Shortest Path from the Plugin Hub inside that client for "Walk there".

Plugin Hub

Once it has had real-world use, the plan is to submit it to the Plugin Hub, after which it installs from the normal client's plugin list like any other and none of the above is needed.

Pairing

  1. Open the web app and read the pairing code it shows (XXXX-XXXX). The app generates one per browser and remembers it.
  2. In RuneLite, open the Wildy Slayer plugin settings, paste the code into Pairing code (with or without the dash) and tick Enable sync. The client warns you that this sends data to a third-party server; accept it.
  3. Log in. The panel's status line goes from "Syncing…" to "Synced Ns ago". The app now sees your levels, task and bank; open your bank once so the plugin can read it, pick a task in the app, and the plugin outlines the gear next time the bank is open.

"Open app" in the panel opens the web app with your code in the URL. Anyone holding the code can read and write that pairing, so treat it like a password; the config field is marked secret and the panel never shows it. "New code" in the app starts a fresh row.

Privacy and rules

  • The plugin sends data about your own account only: display name, combat level, real skill levels, current Slayer task, and the ids and quantities of the items in your bank, inventory and equipment. Each of the three item lists can be turned off. Nothing about other players is read or sent.
  • Data goes only to the Server URL you configured, together with your pairing code, and only while Enable sync is on. Sync is off by default.
  • The server keeps one row per pairing code and prunes rows untouched for 120 days. The plugin writes nothing to disk; its only persisted state is RuneLite's own config for its settings.
  • It never clicks, types, walks or sends anything to the game server, adds no menu entries, changes no interface, and shows nothing about other players, prayers or boss mechanics. The README's "Rules" table maps each Plugin Hub rule to how the plugin complies.
