Wildy Slayer · RuneLite companion

The plugin

Syncs your levels, items and Slayer task with the Wildy Slayer app, outlines its gear picks in your bank and routes to the spot via Shortest Path.

Open the app README (plain text) Sync protocol (plain text)

What it does

  • Sync (opt-in, off by default). While you are logged in, the plugin pushes a snapshot of your own character to the server at most once every 2 seconds after something in it changes, and polls every 5 seconds (configurable) for the selection and setups the app wrote. Everything is keyed by an 8-character pairing code. In the Wilderness, in a PvP area and on a PvP world your inventory and equipment are not refreshed or sent: pushes keep the last ones taken outside those areas (empty lists if none has been taken since you logged in or the plugin started), and a fresh snapshot goes out when you leave.
  • Bank highlights. The app's picks are outlined green, the next-best alternatives yellow, the "what to bring" supplies cyan, in the bank, inventory and equipment tab. Alternatives and supplies can each be turned off, as can outlining in each of the three places. Only items you have are outlined, and gear picks count only for equipable items.
  • Side panel. Sync status, your current task (read from the game, so it shows without pairing too), the app's selection (task, spot, style, setup) with one row per gear slot saying whether the item is worn, in your inventory, in the bank or missing, and your saved setups (at most 60) with an Apply button each.
  • Shortest Path. Show path asks the Shortest Path plugin to draw the route to the selected spot on the map. The spot's coordinates come from a table built into the plugin, not from the server. Clear path is enabled only after this plugin has drawn a route and has not cleared it since, and only until another plugin sets or clears a Shortest Path route; it asks Shortest Path to clear its current route (a destination you set yourself on the world map cannot be detected, so it would clear that too). Auto path on new selection is off by default, and even when on it never fires in the Wilderness, a PvP area, on a PvP world or in an instance. Nothing moves your character.
  • Info overlay. A small on-screen box with your current task (no pairing needed) and the selected task, spot and style.

Install

From the Plugin Hub

  1. In RuneLite, open the configuration panel (wrench icon), click Plugin Hub, search for Wildy Slayer and install it.
  2. Also install Shortest Path from the Plugin Hub; Show path needs it.

The plugin has been submitted to the Plugin Hub and is pending review; until it is accepted it does not show up in the search. The normal RuneLite does not load sideloaded jars, so until then the only way to run it is a development client built from the source (Development below).

Pairing

  1. Open the web app and read the pairing code it shows (XXXX-XXXX). The app generates one per browser and remembers it.
  2. In RuneLite, open the Wildy Slayer plugin settings, paste the code into Pairing code (with or without the dash) and tick Enable sync. The client warns you that this sends data to a third-party server; accept it.
  3. Log in. The panel's status line goes from "Syncing…" to "Synced Ns ago". The app now sees your levels, task and bank; open your bank once so the plugin can read it, pick a task in the app, and the plugin outlines the gear next time the bank is open.

"Open app" in the panel opens the web app with your code in the URL. The pairing code is a bearer token: anyone holding it can read and write that pairing's synced data, like the app key of other sync plugins such as Mystix. Treat it like a password; the config field is marked secret and the panel never shows it. "New code" in the app starts a fresh row.

Privacy and rules

The Plugin Hub listing carries this warning:

This plugin submits your IP address, RSN, skill levels, Slayer task, and bank, inventory and equipment contents to a 3rd-party server not controlled or verified by RuneLite developers.
  • What is sent. Data about your own account only: your RSN (display name), combat level, real skill levels, current Slayer task, and the ids, quantities and names of the items in your bank (as last seen), inventory and equipment, plus the plugin version and a timestamp. The server sees your IP address with every request. Each of the three item lists can be turned off; the next push then sends an empty list. Nothing about other players is read or sent.
  • When. Only while Enable sync is on (off by default) and you are logged in: a push at most once every 2 seconds after your levels, task, bank, inventory or equipment change, and a poll every 5 seconds (configurable) that sends only the pairing code.
  • Wilderness and PvP. In the Wilderness, a PvP area or on a PvP world the plugin does not refresh or send your inventory and equipment; pushes keep the last ones taken outside those areas (empty lists if none has been taken since you logged in or the plugin started), and a fresh snapshot is sent when you leave. After a login, hop or reconnect nothing is pushed until the plugin has read whether you are in such an area. Your RSN, levels, task and bank are sent there as everywhere else.
  • Where. Only to the Server URL you configured (default this site, a Vercel function storing one row per pairing code in a Supabase table), together with your pairing code. The function does not store your IP address.
  • Retention. Rows untouched for 120 days become eligible for deletion and are removed by a best-effort periodic prune. Turning sync off does not delete the row; "New code" in the app starts a fresh one. The plugin writes nothing to disk; its only persisted state is RuneLite's own config for its settings.
  • What the server can make it do. Only choose which of your own items get outlined (equipable items for gear picks, capped lists), and a task and spot from the table built into the plugin. Text from the server appears only in the side panel: at most 60 setup names, each trimmed to 40 characters, and sync error messages trimmed to 60.
  • It never clicks, types, walks or sends anything to the game server, adds no menu entries, changes no interface, and shows nothing about other players, prayers or boss mechanics. The README's "Rules" table maps each Plugin Hub rule to how the plugin complies.

Development

For contributors, or to run unreleased changes. Current RuneLite only turns on developer mode, which sideloading needs, when the client was not started by the RuneLite launcher and Java assertions are on, so a jar dropped into ~/.runelite/sideloaded-plugins/ is never loaded by the normal client. Build a development client from the source instead.

Run it from source (macOS, Linux, Windows)

  1. Java 17 (the plugin itself targets Java 11). macOS with Homebrew: brew install --cask temurin@17. Otherwise install Temurin 17 from adoptium.net. Check with java -version; if several are installed, on macOS run export JAVA_HOME=$(/usr/libexec/java_home -v 17) first.
  2. The source. git clone https://github.com/Zlerp/wildy-slayer, or on the repository page use Code, Download ZIP and unzip it.
  3. Run it. In that folder: chmod +x gradlew once, then ./gradlew run (Windows: gradlew.bat run). The first run downloads Gradle and the RuneLite client, a few minutes. A RuneLite window opens with Wildy Slayer already in the plugin list.
  4. Log in. An old-style username and password account logs in as usual. A Jagex account cannot log in to a development client directly: once, start your normal RuneLite from the Jagex Launcher with the client argument --insecure-write-credentials (set it in the launcher's configuration window, /Applications/RuneLite.app/Contents/MacOS/RuneLite --configure on macOS, launcher 2.6.3 or newer), log in, and it writes ~/.runelite/credentials.properties. The development client then logs in with that file. It is a login token: keep it private, and delete it and remove the argument when you are done. Details: Using Jagex Accounts.
  5. Install Shortest Path from the Plugin Hub inside that client for Show path.
